## **БЛОК 2: Реализация DCA Catch-up Mode (Приоритет P0)**
Реализуй логику "умного старта" для DCA-ботов (`demo_sol_dca` как эталон).

**Требования:**
*   **Механизм:** При запуске бот должен проанализировать последние N свечей (например, 500 свечей H1) и текущую цену, чтобы определить пропущенные уровни DCA.
*   **Логика:**
    1.  Определить базовую цену входа (последний локальный максимум или цена на момент старта бота в прошлом? — сделать это настраиваемым: `start_reference: last_high | start_time`).
    2.  Рассчитать сетку ордеров от этой базовой цены с шагом `grid_step %`.
    3.  Сравнить рассчитанные уровни с уже открытыми ордерами на бирже (через `BybitClient.get_open_orders()`).
    4.  Для уровней, которые находятся **ниже** текущей цены и ещё не имеют открытых ордеров — **немедленно выставить рыночный ордер на усреднение** (минимальным объёмом).
    5.  Для уровней **выше** текущей цены — ничего не делать.
    6.  Для уровней **ниже** текущей цены, которые уже имеют ордера — пропустить.
    7.  Выставить лимитные ордера на все оставшиеся уровни ниже текущей цены.
*   **Безопасность:**
    *   Добавить конфигурационный флаг `catch_up_enabled: bool` в `DCAConfigSchema`.
    *   Максимальное количество catch-up ордеров за один запуск (`max_catch_up_orders: 3`), чтобы не перегружать рынок.
    *   Проверка минимальной нотации по лотам (как в сессии 41 для ETH).
*   **Тесты:**
    *   Написать unit-тесты для логики расчёта пропущенных уровней в `tests/strategies/dca/test_catch_up.py`.
    *   Написать интеграционный тест, имитирующий запуск бота с разными историческими данными.
